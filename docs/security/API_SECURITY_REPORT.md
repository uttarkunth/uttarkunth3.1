## 2. Service-Role Client (`createAdminClient`) Governance Rules

1. **Server-Only Isolation**: `lib/supabase/admin.ts` reads `process.env.SUPABASE_SERVICE_ROLE_KEY` (never `NEXT_PUBLIC_`). Verified via codebase search that `lib/supabase/admin.ts` is **never imported in any `'use client'` component**.
2. **Mandatory Pre-Execution Guard**: Because `createAdminClient()` bypasses PostgreSQL RLS, no route may call `createAdminClient()` before completing:
   - Explicit identity verification (`supabase.auth.getUser()`),
   - Explicit resource ownership or granular staff permission + AAL2 check (`requireStaffPermission(..., { requireMfaAal2: true })`), and
   - Strict schema/input validation (Zod / canonical allowlists).
